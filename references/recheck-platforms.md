# 登录墙平台的公开快照检索与再检索指引

> 适用范围：BOSS 直聘、猎聘、智联招聘、前程无忧 51job、脉脉等**依赖登录态 / cookies 才能看完整 JD 与投递**的平台。
>
> **本 skill 不登录任何平台、不处理 cookies、不内置自动登录。** WorkBuddy 也无法替用户完成登录。
> 但这些平台的**公开快照**仍可被搜索引擎直接索引（如 `site:zhipin.com` / `site:liepin.com` 能返回标题、薪资、公司、部分 JD 摘要）。
> 因此做法是：**直接 `site:` 公开快照检索，结果一律标「⚠️ 需手动复核」并附再检索线索**，由用户在自己已登录的 App 内确认在招与投递。

---

## 一、检索方式（免登录，直接搜）

对目标平台直接用 WebSearch 发起 `site:` 检索，无需任何登录态：

```
site:zhipin.com AI产品运营 实习生 上海
site:liepin.com AI产品运营 实习生 深圳
site:zhipin.com 大模型 产品运营 实习 杭州
site:51job.com AI 运营 实习生 北京
site:zhaopin.com AI产品运营 实习生 上海
site:maimai.cn AI 产品运营 内推
```

- 检索密度、关键词组规则同 `platforms-cn.md` 第六节，与其它平台完全一致。
- **不要因为"需要登录"就跳过这些平台**——公开快照里往往已经有足够信息判断匹配度，跳过去只会漏掉真岗。
- 节奏：正常 WebSearch 即可，无需特殊限速；只是**不要对同一个平台在短时间内高频狂刷**。

---

## 二、采集时必须记录「再检索线索」（关键）

登录墙平台的链接往往点开就是登录墙、AI 验活也判不了（`verify_links.py` 会落 `unknown`，再由 `report.py` 标「⚠️ 需手动复核」）。
所以**采集阶段就要把用户能在自己 App 里重新找到这条岗位的信息存全**，否则交付后用户无从复核。

每条岗位 JSON 必须尽量填全以下字段：

| 字段 | 含义 | 示例 |
|------|------|------|
| `title` | 岗位名称（必有） | 海外增长运营实习生(AI产品) |
| `post_title` | 帖子 / 内推帖标题（若来源是帖子而非官招页） | 【内推】智启心源 海外增长运营实习 |
| `author` | 作者 / 发帖人 / HR 昵称 | HR-Kelly、某大厂内推组 |
| `posted` | 发送 / 发布时间 | 2026-07-28、3天前 |
| `source` | 来源平台 | BOSS直聘、猎聘、智联、51job、脉脉 |
| `link` | 搜到的公开链接（详情页优先，列表页也行，但要标注） | https://www.zhipin.com/gongsi/job/xxx.html |
| `needs_recheck` | **固定置 `true`**，触发报告里的「⚠️ 需手动复核」标识与再检索线索块 | true |

> 拿不到的字段填空字符串 `""`，**不要杜撰**。能拿到多少算多少，但 `title` + `source` 至少要有。

`report.py` 会自动把这些字段拼成「再检索线索：岗位名｜帖子标题｜作者/发帖｜发送时间｜来源」显示在 HTML 卡片与 Excel 备注列，用户照着就能在 App 内搜到原帖。

## 三、质检与验活（与免登录平台一致，但结局不同）

- 链接验活闸门（`verify_links.py`）照常跑：L1 脚本对登录墙链接必然落 `unknown`（跳登录墙 / 安全验证），L2 AI 也打不开 → 判 `unsure`。
- 这类岗位的 `verify_status` 最终是 `unknown` / `unsure`，`report.py` 会：
  - 验活徽标显示为 **「⚠️ 需手动复核」**（而非「❓ 无法确认」的死亡暗示）；
  - 卡片内渲染**再检索线索块**；
  - 报告顶部黄色横幅提示「本报告含 N 条登录墙平台岗位，请 App 内自行确认」。
- **铁律不变**：抓不到内容一律判 `unknown` 保留，绝不因"抓不到"就判 `dead` 误删（登录墙极常见，误删会丢掉真实好岗）。

---

## 四、交付话术（给用户）

对带「⚠️ 需手动复核」的岗位，必须提醒：

> 以下岗位来自 BOSS / 猎聘 / 智联 / 51job 等登录墙平台，AI 无法直接确认是否仍在招。
> 请在该平台 App 内用「公司名 + 岗位名」或报告里的再检索线索（帖子标题 / 作者 / 发送时间）自行确认在招并投递，
> 不要直接相信本报告链接——链接点开可能是登录页。

---

## 五、为什么不要"先登录再搜"

- WorkBuddy 没有用户登录态，也**不应**索要 / 存储任何平台的账号凭证（安全红线）。
- 即使用户在自己的浏览器登录了，把 cookies 导出给 AI 抓取也属于越权且易触发平台风控（账号异常验证）。
- 公开快照检索已经能覆盖"找岗 + 初步匹配"的需求；"确认在招 + 投递"这一步本就该由用户在自己账号内完成。

> 一句话：**我们负责把登录墙平台里的岗"捞出来给你看"，确认和投递交还给你。**
