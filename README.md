# 📡 岗位雷达 job-radar

> **你的中国大陆求职雷达** —— 零配置、覆盖全平台、链接验活闸门、跨天去重。
> 把「每天手动刷 5 个 App、还怕漏掉好岗、点开一条已是「职位已下架」」，
> 变成「每天 8 点一份自动生成、已验活、已去重的岗位日报」。开源、免费、谁拿到都能用。

---

**适用人群**：正在找实习 / 校招 / 社招，方向不限（AI 产品、开发、算法、运营、设计……），
只要你在中国大陆求职、且受够了「刷不完的平台 + 点不开的死链」。

> 本仓库是一个**标准 skill 包**（对齐 [CareerForge](https://github.com/rebecha1227-a11y/CareerForge) 的 `SKILL.md + references + scripts + templates` 结构），
> 把 CareerForge 的 job-hunt「如何搜岗位」方法论，落成一个**不绑定任何调度器、任何人克隆即用**的脚手架。

## 它能做什么

| 能力 | 说明 |
|------|------|
| 🌐 **全平台覆盖（16+ 源）** | 实习垂类（实习僧/应届生/海投/刺猬）、官方与公共渠道（国聘/24365/高校就业网/大厂官网）、综合平台、内容社区（V2EX/掘金/公众号）；**含 BOSS/猎聘/智联/51job/脉脉 免登录公开快照检索** |
| 📄 **简历驱动** | 上传简历文件 / 粘贴文本 / 口述背景，AI 据此提取画像、检索并打分，匹配度更准 |
| 🚧 **链接验活闸门（代码级，不可绕过）** | 两层把关：先机械验活（URL→状态码→重定向→失效文案）移除死链、降级列表页；脚本判不了的（反爬/登录墙/JS 渲染）导出交 AI 用 WebFetch 逐条语义裁决。**两层任一没做完，`run.py` 直接中止、不出报告**——提示词会被偷懒绕过，代码闸门不会 |
| 🔁 **跨天去重** | 以**岗位链接**为主键、**描述文本**为辅助键，**绝不**只靠「公司+岗位名+城市」判重（那会把同公司同名不同岗误合并）；只推真正发生变化的岗位 |
| 🟢🟡🟠 **分级报告** | 🟢高度匹配 / 🟡基本匹配 / 🟠可尝试；同时产出 **Excel（可点击链接、三档配色、自动筛选）** 与 **HTML** 报告，纯标准库生成，无需 openpyxl |
| ⏰ **每日自动化** | 配一次自动化任务，每天 08:00 自动检索 → 验活 → 去重 → 报告 → 推送；报告带当天验活时间戳 |
| 📁 **自定义保存路径** | 首次问答即可指定数据文件夹，去重库与报告自动存到那里，跨会话不丢、分享也不混私人数据 |
| 🔒 **登录墙平台同样直接搜** | BOSS/猎聘/智联/51job/脉脉 依赖登录态看完整 JD，但其**公开快照仍可被搜索引擎直接索引**；一律 `site:` 公开快照检索，**不进入任何登录流程、不处理 cookies**，搜到的岗位标「⚠️ 需手动复核」并附再检索线索 |

## 安装

### 方式一：一键安装到 AI 工具（推荐）

在仓库根目录运行安装脚本，它会自动检测你已安装的 AI 工具并装入：

```bash
bash install.sh
```

支持的 AI 工具：Claude Code、Codex CLI、Cursor、Gemini CLI、Trae（国际/国内）、
OpenCode、Rovo Dev、Hermes、**WorkBuddy**。安装后，在对应工具里用自然语言触发即可，例如：
「帮我搜一下上海 AI 产品运营的实习岗」。

### 方式二：纯命令行手动使用（不依赖任何 AI 界面）

```bash
python scripts/brief.py      # 中文问答：填简历(核心) → 选方向/城市 → 确认检索平台 → 指定保存路径
# 打开生成的 prompt.txt，把内容完整发给任意 AI
# 把 AI 返回的岗位 JSON 保存为 jobs_raw.json

python scripts/run.py --verify   # 自动验活→清洗死链→去重→出报告（推荐）
```

若遇到强反爬平台（51job / BOSS / 猎聘 / 智联）链接，脚本会判 `unknown` 并在门禁处拦下，
需 AI 做第二层语义验活才放行：

```bash
python scripts/verify_links.py --export-unknown   # 导出待裁决清单 verify_unknown.json
# 交给 AI：逐条打开链接，把每条的 l2_status 填成 alive / dead / unsure，另存为 verify_l2.json
python scripts/verify_links.py --import-l2        # 回写裁决：dead 自动移除，alive 标记「AI已复核」
python scripts/run.py                             # 门禁放行，出报告
```

实在没法做 L2 时用 `python scripts/run.py --allow-unknown` 放行，报告会打「含未确证链接」水印。

### 方式三：让 AI 帮你装

把仓库链接发给你的 AI，说：「clone 这个仓库并运行里面的 install.sh 安装 job-radar skill」。

## 快速开始（两种用法）

**A. 用 AI 工具（最省事）**

> 你：帮我搜一下上海、杭州的 AI 产品运营实习岗，每天 8 点推给我。
> AI：先跑 `brief.py` 收集需求（简历/方向/城市/平台/保存路径），然后每天定时检索、验活、出报告并推送到你指定的渠道。

**B. 纯脚本（自己掌控）**

```bash
python scripts/brief.py        # 交互问答，约 1 分钟，生成 prefs.json + prompt.txt
# ↑ 其中「数据保存路径」一步可填 D:/岗位雷达 这类绝对路径，之后报告与库都存那里

# 把 prompt.txt 发给任意 AI，拿回岗位 JSON 存为 jobs_raw.json
python scripts/run.py --verify # 一条龙：验活 → 去重 → 报告
# 报告在 <数据目录>/reports/report-YYYY-MM-DD.html 与 .xlsx
```

常用命令：

| 命令 | 作用 |
|---|---|
| `verify_links.py --lint` | 只做 URL 形态静态体检，不联网、零成本 |
| `verify_links.py --apply` | 联网验活并写回：移除死链、降级列表页 |
| `verify_links.py --check` | 门禁检查（`run.py` 内部调用），退出码 2 = 不通过 |
| `verify_links.py --selftest` | 回归自测（改判定规则后必跑） |
| `jobstore.py stats` | 查看去重库总数、各档位、疑似下架数 |
| `jobstore.py applications` | 查看你的投递进度 |

## 配置

### 数据保存路径（新手必看）

首次运行 `brief.py` 的**第零步**会问「数据保存路径」：

- 默认 `~/.job-radar`（你的用户目录下的隐藏文件夹）；
- 想存到自己的文件夹（如 `D:/岗位雷达`）？直接填绝对路径，脚本会帮你建好；
- 之后所有去重库（`data/jobs.db`）、报告（`reports/`）都进这个文件夹；
- 后续 `run.py` / `jobstore.py` / `report.py` 会**自动沿用**你选的路径，不用每次指定。

> 这样数据长期累积、跨会话不丢，而且分享仓库时不会混进你的私人岗位数据。

### 推送渠道

写在 `profile/push-config.md`（首次需自己建，模板见 `references/push-config.example.md`）：

- **渠道一：微信 Claw（手机收日报，推荐）** —— WorkBuddy 设置里连「微信助理集成」并启用；
- **渠道二：邮箱（Agent Mail）** —— 连 Agent Mail 连接器后填收件地址；
- **渠道三：企业微信 / 飞书群机器人** —— 填 webhook 即可，无需连连接器；
- **渠道四：本地报告** —— 默认开启，`reports/` 下自动生成，无需配置。

### 每日自动化

打开 AI 工具的「自动化」，参考本仓库 `automation-prompt.example.md`：
把「任务一 / daily 模式」整段 prompt 复制进去，`{JOB_RADAR_DIR}`/`{USER_NAME}`/`{DIRECTION}` 换成你的值，
时间设 **08:00**，工作目录(cwd) 设为你的数据目录。该任务已把登录墙平台的公开快照一并检索，无需单独任务。

## 登录墙平台怎么办（BOSS / 猎聘 / 智联 / 51job / 脉脉）

这些平台依赖登录态才能看完整 JD 与投递，但**公开快照（被搜索引擎收录的 listing）仍可直接索引**。

每日检索**已经把它们一并搜了**，搜到的岗位标「⚠️ 需手动复核」并附再检索线索
（岗位名 / 帖子标题 / 作者 / 发送时间 / 来源）。你拿这些线索在对应 App 内确认在招并投递即可。

**本 skill 不登录任何平台、不要求你先登录**，所以没有「先登录再提醒」的环节。详见 `references/recheck-platforms.md`。

> ⚠️ 登录墙平台的岗位为公开快照检索结果，AI 无法 100% 确认是否仍在招，
> 投递前请在对应 App 内用报告里的再检索线索自行确认在招。

## 兼容性 / 依赖

| 项目 | 要求 |
|------|------|
| Python | 3.8+，仅用**标准库**（无需 `pip install`） |
| AI 工具 | 任意支持 skill 的 AI 助手（WorkBuddy / Claude Code / Codex / Cursor …） |
| 联网检索 | 需要 AI 具备 **WebSearch / WebFetch** 能力（这是岗位检索的核心依赖） |
| 推送 | 微信 / 邮件 / webhook 任选，本地报告零配置 |

- 模型无关：只要 AI 能执行搜索并返回 JSON，任何模型都行；门禁与去重是脚本负责，不依赖模型强弱。

## 去重逻辑说明（为什么不是「指纹」）

旧版用 `(公司 + 岗位名 + 城市)` 做哈希指纹，会把同一家公司「同名不同岗」误合并。本版改为：

1. **主键 = 归一化链接**：剥离 `https://`、`www.`、末尾斜杠、跟踪参数（`utm_*`/`from`/`spm`）。
   同一帖子被不同聚合站转载、或换来源参数重发，都判为同一岗位。
2. **辅助键 = 描述哈希**：仅在「同公司 + 同标题 + 描述文本高度一致」时判重，避免误并。
3. **无链接无描述**的纯快照 → 一律视为新岗位（宁可重复也不漏）。

这样：同公司同名不同岗一定保留；跨天同一帖子一定去重。
